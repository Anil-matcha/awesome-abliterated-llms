# Contributing

Help keep the model guide accurate and useful for developers.

## Entry requirements

1. Confirm that the exact Muapi endpoint is live. Include the endpoint slug and a working Muapi family landing page.
2. Record the date checked and the model's supported inputs and request controls from the current API schema or landing page.
3. Link a primary source for the model family when available. Do not present a family source as proof of a derivative checkpoint.
4. Keep prices linked to the live page unless a dated price snapshot is necessary; state the currency and token basis if included.
5. Separate observed refusal behavior from factuality, quality, latency, and tool support. Include a reproducible test setup for behavior claims.
6. Do not infer licenses, privacy properties, training data, or upstream weights from a route name.
7. Keep examples limited to lawful, consensual use. Do not include personal data or real-person sexual examples.

## Pull request checklist

- [ ] Endpoint is live and the slug is exact.
- [ ] Muapi landing page and playground links resolve.
- [ ] Inputs, limits, pricing, and stream behavior are supported by current documentation.
- [ ] Claims are qualified and evidence is linked.
- [ ] No duplicate model entry or broken Markdown link was introduced.
